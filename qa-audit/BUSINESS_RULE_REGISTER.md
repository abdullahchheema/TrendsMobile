# Business-rule register

Each rule as the system actually implements it, where it lives, which audit test proves it, and how sure the rule itself is.

Rule status:
**Code+docs** = the code and a guide in the repository agree. **Constraint** = also enforced by the database. **Decision** = the behaviour is implemented but the policy behind it is not written down anywhere, or two parts of the system do it differently; an owner or accountant should confirm it. **Missing** = the brief expects it and the system does not have it. **Contradiction** = the code said one thing and did another (and what was done about it).

Test names are in `offline/shop/tests_audit_*.py` (shortened: `calc` = `tests_audit_calculations`, `acct` = `tests_audit_accounting`, `online` = `tests_audit_online`, `shop` = `tests_audit_shop`, `race` = `tests_audit_concurrency`, `sec` = `tests_audit_security`).
